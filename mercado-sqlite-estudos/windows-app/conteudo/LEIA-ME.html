02 / Sua primeira consulta

Faça uma pergunta pequena.

Quais são os dez primeiros produtos? Copie o bloco abaixo, cole no editor e clique em Run. As palavras-chave podem ser escritas em maiúsculas ou minúsculas; os nomes usados aqui estão em português.

SELECT id,
       nome,
       unidade,
       ROUND(preco_venda_centavos / 100.0, 2) AS preco_reais
FROM produtos
ORDER BY id
LIMIT 10;

SELECT escolhe as colunas; FROM escolhe a tabela; ORDER BY ordena; LIMIT limita a quantidade de linhas.

Agora conecte duas tabelas

O produto guarda categoria_id. O JOIN encontra a categoria cujo id corresponde a esse valor e traz seu nome.

SELECT p.nome AS produto,
       c.nome AS categoria,
       ROUND(p.preco_venda_centavos / 100.0, 2)
         AS preco_reais
FROM produtos AS p
JOIN categorias AS c
  ON c.id = p.categoria_id
ORDER BY p.id
LIMIT 10;

p e c são apelidos das tabelas. AS também permite dar um nome legível à coluna exibida.

Uma pergunta de negócio

Quanto cada loja faturou em vendas concluídas? A view já calcula o total de cada venda, com os descontos dos itens.

SELECT l.nome AS loja,
       COUNT(*) AS vendas_concluidas,
       ROUND(SUM(v.total_centavos) / 100.0, 2)
         AS faturamento_reais
FROM vw_vendas_resumo AS v
JOIN lojas AS l ON l.id = v.loja_id
WHERE v.status = 'CONCLUIDA'
GROUP BY l.id, l.nome
ORDER BY faturamento_reais DESC;

WHERE filtra linhas; GROUP BY forma grupos; SUM soma; COUNT conta.

03 / Entenda o modelo

As tabelas se conectam por identificadores.

Chave primária (PK) identifica uma linha, normalmente a coluna id. Chave estrangeira (FK) aponta para uma linha de outra tabela, como vendas.loja_id → lojas.id. Uma relação 1:N significa que uma linha pode estar ligada a várias linhas do outro lado.

Exemplo 1:N: uma venda tem vários itens. Exemplo N:N: um produto pode ser oferecido por vários fornecedores, e um fornecedor pode oferecer vários produtos. A tabela produto_fornecedores guarda cada combinação e seu custo. Em estoques, a combinação (loja_id, produto_id) é a própria chave primária.

04 / Leia antes de somar

Seis regras para respostas corretas.

1. Dinheiro fica em centavos

1299 significa R$ 12,99. Use / 100.0 para exibir reais sem divisão inteira. Quantidades de produtos KG podem ter até três casas decimais; UN indica unidade.

O total de cada item é arredondado para o centavo, antes da soma. Para consultas financeiras, use vw_itens_venda e vw_vendas_resumo: as views já fazem esse cálculo de forma consistente.

O desconto já é o valor total do item, não um desconto por unidade. Em vw_itens_venda, total_centavos já inclui esse desconto.

2. O período é fixo

Vendas e compras cobrem janeiro a setembro de 2026. Datas usam o padrão ISO AAAA-MM-DD; datas com horário seguem a mesma ordem.

WHERE data_venda >= '2026-01-01'
  AND data_venda <  '2026-10-01'

O limite final exclusivo inclui todo o dia 30/09. Evite date('now'): os resultados mudariam conforme a data em que você estuda.

3. Status define o movimento

Para faturamento e saída de estoque, use vendas status = 'CONCLUIDA'. Vendas canceladas não entram nesses cálculos.

Compras podem ser RECEBIDA, PENDENTE ou CANCELADA. Somente as recebidas entram no estoque. ativo = 1 representa verdadeiro; 0, falso.

4. Ausência também é informação

cliente_id IS NULL significa venda anônima. Use IS NULL, nunca = NULL. Um LEFT JOIN preserva essas vendas ao buscar o nome do cliente.

Também existem clientes sem compras e produtos sem vendas. Explore LEFT JOIN e NOT EXISTS para encontrá-los.

5. Estoque é um retrato

O estoque tem referência em 30/09/2026: abertura em 01/01 + compras recebidas − vendas concluídas = quantidade atual.

Não há triggers para atualizá-lo automaticamente. Ao inserir ou alterar movimentos para praticar, o retrato não se recalcula sozinho.

6. Custo e margem têm contexto

Os itens guardam preço e custo da época da venda. Para estimar margem bruta histórica, use o total líquido menos o custo total desses itens.

O preço e o custo em produtos são os valores do cadastro. A margem deste estudo não desconta impostos, salários ou outras despesas; não representa lucro líquido.

A armadilha do JOIN entre dois detalhes. Uma venda com 3 itens e 2 pagamentos gera 6 linhas se você juntar os dois diretamente. Somar valores depois disso duplica os totais. Some os itens e os pagamentos separadamente por venda_id e só então junte os resultados. A vw_vendas_resumo já entrega o lado dos itens resumido em uma linha por venda.

Uma dica antes de tentar

Combine ativo = 1 com BETWEEN 1000 AND 2500, pois o preço armazenado está em centavos.

Ver SQL, explicação e resultado
Consulta completa · SQLite
SELECT id, nome, unidade, preco_venda_centavos / 100.0 AS preco_reais
FROM produtos
WHERE ativo = 1
  AND preco_venda_centavos BETWEEN 1000 AND 2500
ORDER BY preco_venda_centavos, id;
Como a consulta funciona

WHERE mantém somente os produtos que atendem às duas condições ligadas por AND. BETWEEN inclui os limites de 1000 e 2500 centavos, portanto produtos de exatamente R$ 10 ou R$ 25 entram na lista. ORDER BY usa o preço para ordenar e o id para desempatar, ajudando a comparar opções ativas na mesma faixa de preço.

SELECT COUNT(*) AS quantidade_produtos,
       MIN(preco_venda_centavos) / 100.0 AS menor_preco_reais,

           COALESCE(p.quantidade_pagamentos, 0) AS quantidade_pagamentos,
           CASE WHEN v.status = 'CONCLUIDA' THEN v.total_centavos ELSE 0 END
               AS valor_esperado_centavos,
           COALESCE(p.valor_pago_centavos, 0) AS valor_pago_centavos
    FROM vw_vendas_resumo AS v
    LEFT JOIN pagamentos_por_venda AS p ON p.venda_id = v.venda_id
)
SELECT venda_id, status, quantidade_pagamentos,
       valor_esperado_centavos / 100.0 AS valor_esperado_reais,
       valor_pago_centavos / 100.0 AS valor_pago_reais,
       (valor_pago_centavos - valor_esperado_centavos) / 100.0 AS diferenca_reais
FROM conferencia
WHERE valor_pago_centavos <> valor_esperado_centavos
ORDER BY venda_id;
Como a consulta funciona

A primeira CTE reduz os pagamentos a uma linha por venda com sua quantidade e soma, e o LEFT JOIN preserva até vendas sem pagamento. CASE define como esperado o total líquido de uma venda concluída ou zero de uma cancelada; COALESCE representa a ausência de pagamentos como zero. O WHERE compara centavos inteiros antes da conversão para reais, e só mostra problemas; no banco original, o resultado vazio confirma que todos os valores conferem.
